# SafeEdge HazardGuard — System Demonstration Guide

This guide provides a comprehensive, step-by-step walkthrough for demonstrating the **SafeEdge HazardGuard** system without requiring physical hardware. It showcases the end-to-end telemetry pipeline: simulated IoT node data generation, FastAPI ingestion, SQLite/PostgreSQL persistence, real-time hazard evaluation, and Streamlit cockpit visualization.

## Step 7: Connecting Physical ESP32 Hardware (Future Deployment)

When physical hardware is acquired:

### 7.1 Hardware Assembly & Wiring
1. **DHT22 Sensor:**
   - Pin 1 (VCC) -> ESP32 3.3V
   - Pin 2 (DATA) -> ESP32 GPIO 4 (with 10k pull-up resistor to 3.3V)
   - Pin 4 (GND) -> ESP32 GND
2. **MQ-135 Gas Sensor:**
   - VCC -> 5V external power supply (draws ~150 mA heater current)
   - GND -> Common GND
   - AO (Analog Out) -> **Voltage Divider** (10k resistor from AO to GPIO 34, 20k resistor from GPIO 34 to GND) to protect ESP32 3.3V input limit.
3. **MAX9814 Microphone:**
   - VDD -> ESP32 3.3V
   - GND -> ESP32 GND
   - OUT -> ESP32 GPIO 35 (ADC1_CH7)

### 7.2 Flashing Firmware
1. Open [`firmware/esp32_sensor_node/esp32_sensor_node.ino`](file:///d:/Antigravity/safety%20from%20hazardeous%20gases/firmware/esp32_sensor_node/esp32_sensor_node.ino) in Arduino IDE.
2. Install libraries: `DHT sensor library` by Adafruit, `ArduinoJson` (v6 or v7).
3. Select Board: **ESP32 Dev Module**.
4. Upload firmware over USB.

### 7.3 Live Hardware Operation
- **Via USB Serial:** Connect USB cable, open dashboard, select **Live Hardware Mode (ESP32 Serial)**, select your COM port, and click **Connect ESP32**.
- **Via Cloud Wi-Fi:** Enter your Wi-Fi credentials in `config.h` and the public backend URL (`https://your-backend.onrender.com/api/v1/telemetry`). The ESP32 streams telemetry autonomously from anywhere with Wi-Fi.
